# 案例：淘宝直播间货盘调研（李佳琦直播间·洗发水）

> 2026-10-28 实跑通过。目标：单场直播的洗发水货盘全景（品牌/卖点/机制/价格/加购热度），输出 CSV 货盘表 + 汇总洞察。
> 本案例未依赖任何官方后台数据——淘宝直播没有罗盘式入口，浏览器是唯一通道。

## 工作流（三段式）

```
① 直播间取数（直播进行中，taskSpace 常驻）
   直播间页面商品池 → 搜索「洗发水」→ 命中 24 个挂链
   → 提取卡片字段：位置序号 / 机制话术 / 直播间价 / 价格标签(补贴后|优惠后) / 商品ID
        ↓ merged.json（卡片层）
② 天猫详情页补全（scrape_detail.js）
   24 个商品 ID → detail.tmall.com 批量抓取
   → 正则提取：标题 / 加购人数 / 已售 / 详情价 / 参数块
        ↓ detail_fresh.json（详情层）
③ 合成与洞察（build.js + summary.js）
   卡片层 × 详情层 merge → 货盘 CSV
   → 品牌布局 / 卖点分布 / 价格带 汇总行
```

## 文件说明

| 文件 | 作用 |
|---|---|
| `scrape_detail.js` | ego 脚本：taskSpace + page.goto + evaluate 正则提取，单页 4.2s 节流 |
| `build.js` | 卡片数据（机制/价格/序号）与规格映射，merge 成货盘记录 |
| `summary.js` | 汇总洞察行（品牌 SKU 数、卖点分布、价格带） |
| `sample_货盘.csv` | 产出物样例（节选） |

## 关键经验

1. **两层取数结构**：直播间卡片层只有机制话术和直播间价，缺加购/销量——补一层天猫详情页正则提取，两层数据用商品 ID 对齐
2. **价格标签要区分**：直播间价有「补贴后/优惠后」两种口径，混用会导致价格带分析失真
3. **节流**：详情页逐个抓 + 4.2s 等待，24 个商品约 2 分钟跑完，无风控触发
4. **正则优先于 DOM 结构**：详情页 DOM 复杂多变，从 innerText 里正则抓「已售/加购/￥」比解析 DOM 稳
5. 挂链含已下架商品，统计时区分在售/下架
